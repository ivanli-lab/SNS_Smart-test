# SNS Stream - 程式流程文件

## 概述

本文件詳細說明 SNS Stream 系統的核心執行機制，包括伺服器啟動、測試執行流程、以及前後端進度同步機制。

## 伺服器啟動流程

1.  **環境變數載入**：讀取 `.env` 檔案配置。
2.  **模組初始化**：載入 Express、Playwright 及各測試工具路由（`check.js`, `check2.js`, `check3.js`）。
3.  **日誌系統建立**：自動建立 `logs/` 目錄，並覆寫 `console` 輸出以實現雙重記錄（終端 + 檔案）。
4.  **路由註冊**：註冊 `/api/check`、`/api/check2`、`/api/check3` 等 API 端點。
5.  **啟動監聽**：伺服器於指定埠號（預設 3000）啟動。

## 測試執行完整流程

1.  **用戶觸發**：用戶在前端介面輸入 URL 並點擊「開始測試」。
2.  **請求接收**：後端路由接收請求，重置進度狀態。
3.  **瀏覽器啟動**：Playwright 啟動 Chromium，導航至目標 URL。
4.  **測試循環**：
    *   **設定步驟**：調用 `setCurrentStep` 更新當前進度。
    *   **執行模組**：調用 `scripts/steps/` 下的對應模組執行測試動作。
    *   **更新結果**：調用 `updateStepResult` 儲存執行結果。
5.  **進度同步**：前端每 700ms 輪詢一次 `/api/progress`，動態更新 UI。
6.  **測試完成**：
    *   **Lobby/Live Slot**：等待 3 秒後關閉瀏覽器。
    *   **SAC 後台**：執行「視窗焊死」邏輯，保持所有分頁開啟。
7.  **結果呈現**：前端顯示最終統計與 `Run History`。

## 錯誤處理與資源清理

*   **異常捕獲**：使用 `try-catch` 確保測試失敗時能記錄錯誤並截圖。
*   **資源釋放**：在 `finally` 區塊中確保進度重置與（非 SAC 情況下的）瀏覽器關閉。
*   **SAC 特殊處理**：SAC 測試成功後不進入 `finally` 的關閉邏輯，而是無限期等待，直到手動關閉。

## 總結

SNS Stream 的流程設計強調**即時性**與**穩定性**。透過模組化的步驟執行與高頻率的進度同步，確保測試過程透明且易於追蹤。
